Password Vault (Lite)

A personal encrypted vault for credentials, inside your own Odoo database

Every business keeps a handful of logins that are not in Odoo: the bank portal, the courier account, the domain registrar. They usually end up in a spreadsheet called passwords.xlsx, or in a chat message. This module gives each user a private vault in the database you already run and back up, with passwords encrypted at rest using a key that is deliberately kept outside the database.

What it does

Real encryption, not obfuscation

Secrets are sealed with Fernet from the cryptography library Odoo already ships: AES-128-CBC with an HMAC-SHA256 tag and a fresh random IV for every value. A tampered value is refused, not silently mis-read.

The key is not in the database

The master secret is read from the DRKDS_VAULT_KEY environment variable or from drkds_vault_key in odoo.conf. A system parameter would sit in the same backup file as the ciphertext and protect nobody.

A key per database

The configured secret is stretched with PBKDF2-HMAC-SHA256 over 240 000 iterations, salted with the database's own uuid. A ciphertext copied into another database cannot be opened there.

Write-only password field

You type a password in; it never reads back. It is not stored in the ORM read path, cannot be searched on, and is excluded from exports.

Reveal is an act, and it is logged

Seeing a password means clicking Reveal. That writes a line in the entry's access log with the user and the timestamp. Storing and changing a secret are logged too.

Yours alone

Global record rules limit entries, folders, tags and log lines to their owner. There is no manager group and no administrator override, because a vault with an override is not a vault.

Need the full version? The drkds Password Vault app adds team vaults, controlled sharing, rotation reminders and password strength auditing.

Good to know

  • Set a long random key before use: python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())", put it in odoo.conf as drkds_vault_key, and restart Odoo.
  • If the key is missing, too short or wrong, the vault raises an error. It never falls back to storing a password in clear text, and it never decrypts to garbage.
  • Back up the key separately from the database. Lose the key and the stored passwords are gone; there is no recovery path, by design.
  • Titles, URLs, usernames, notes, folders, tags and the access log are metadata and are not encrypted. Keep passwords out of the notes field.
  • Record rules are enforced by the Odoo ORM. A PostgreSQL superuser, or anyone who can run server-side Python on the instance, can read every row and can also read the key from the process environment; what this protects is a stolen dump or backup.
