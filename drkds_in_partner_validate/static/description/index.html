India Partner Identifier Validation

Validate GSTIN, PAN, IFSC and PIN code on contacts, with checksum and state cross-check

Wrong Indian identifiers are caught the moment a contact is saved, so bad data never reaches an invoice, a return working paper or a payment file. Every check runs offline inside your own database.

What it does

GSTIN with check digit

Fifteen character structure plus the official check-digit algorithm, so a transposed or invented number is rejected, not merely a malformed one.

PAN with holder type

Five letters, four digits, one letter, including a check on the fourth character that identifies the type of holder.

IFSC and PIN code

Eleven character IFSC with its reserved zero, and six digit Indian PIN codes that never start with zero.

State cross-check

The first two digits of a GSTIN are the state code. If they disagree with the state on the address, the save is refused.

PAN inside GSTIN

Characters three to twelve of a GSTIN are the PAN. If both fields are filled and disagree, the save is refused.

Duplicate notice

Another contact carrying the same GSTIN raises a visible notice, never a block, because branches of one business legitimately share a PAN.

Good to know

  • Input is normalised on save: spaces, dashes, dots and lower case are cleaned up for you.
  • Every identifier is optional. Nothing here forces a contact to carry one.
  • GST state codes are ordinary records, so a new state or union territory is a data change, not a code change.
  • Depends on the base module only. Nothing else is pulled into your database.
  • No outbound network calls of any kind. Every check is computed locally.

This module is a tool to assist with compliance workflows. Responsibility for statutory compliance rests with the user and their tax professional.
