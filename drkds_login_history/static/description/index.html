Login History

Who signed in, from where, and which attempts failed

Odoo Community keeps the devices behind sessions that succeeded. It does not keep the attempts that failed, the login name somebody typed, or the moment a session ended. Login History records all of it in one table a Settings administrator can read, filter and chart.

Every row is written through its own database connection, so a failed attempt is kept even though Odoo rolls the failed request back. Recording never blocks a login, and no data ever leaves your server.

What it does

Every attempt, not only the good ones

One row per success, failure or logout, with the login name exactly as typed, the matched user (archived accounts included), the time, the IP address and the browser string. Browser form, JSON-RPC, XML-RPC and passkey logins are all covered.

Honest about two-factor logins

A right password that still waits for its 2FA code is recorded as 2FA Pending, not as a success. The code step then adds its own Success or Failed row, so a stolen password stopped by 2FA stands out.

Browser and operating system

Read from the browser string by a small parser of our own. No external library, no signature database to update.

Filters and a chart

Today, Last 7 Days (both in your timezone), Failed, Success, 2FA Pending, Logout and Unknown Login Name, grouped by user, result, day or IP address, plus a bar chart of events per day stacked by result.

On the user form

A Login History button shows the failed attempts of today and the last successful login, and opens that user's rows.

Automatic housekeeping

A daily scheduled action deletes rows older than the number of days you set in General Settings (default 180, 0 keeps everything).

Administrators only

The menu, the action, the model and the figures on the user form are limited to Settings administrators. Rows cannot be created or edited from the interface.

Good to know

  • Depends on base, web and base_setup only. Odoo 19 Community.
  • Recording starts with the first login after installation; nothing is back-filled.
  • The session identifier is never stored, only a SHA-256 hash of it.
  • API-key calls are not logins: only the authenticate call of an integration is recorded, never each request it makes.
  • Values sent by the client are cut to a fixed length (login 255, browser string 1024, address 64 characters).
  • The Country field stays empty by design: no geolocation lookup, no outbound call, no telemetry.
  • Behind a reverse proxy, enable Odoo's proxy mode so the IP address is the real client address. Without proxy mode, X-Forwarded-For is ignored.
